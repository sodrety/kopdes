# Reviewed collection amounts and mandatory confirmation

New exports contain two sheets. `Tagihan` is a read-only member collection summary. Mandatory and voluntary savings are automatically collected in full using member configuration, without actual savings input columns. Its status is displayed as automatically paid, loan actuals N–Q summarize `Rincian Pinjaman`, R is the total collection and S the difference. Editing reference savings amounts, status or loan summary cells does not override authoritative collections. Savings are saved only after preview and confirmation.

`Rincian Pinjaman` contains one row per eligible loan and statement month, keyed by Loan ID and Member ID. It displays previous arrears, the current installment, the total current bill, the suspension fee, dates and loan type. Select Payment and enter actual loan payment in column M, including zero. A blank action records nothing for that loan. Loan actions operate independently from automatically paid savings. Two simultaneous loans of one type can be paid independently; the importer never reallocates one detail row to another loan. It allocates a loan's actual payment across that loan's unpaid installments oldest first. Unpaid installment amounts remain arrears.

Select the explicit suspension action and enter a reason to suspend a particular loan. Column M must be zero; the monthly fee is separate from repayment and must match the authoritative fee snapshot. The existing suspension transaction credits COA 40201 without reducing the loan obligation and shifts eligible installments one calendar month. Preview displays the deferred amount separately from unpaid arrears. Normal zero/partial payments never suspend a loan.

Amounts must be nonnegative whole Rupiah. Savings always use configured contributions; each loan payment cannot exceed its currently due installments. Reference loan IDs, ownership, statement month and actual amounts are validated against authoritative application state. Duplicate Loan IDs, foreign members, unsupported actions, payments combined with suspension and ambiguous combinations of detail/legacy sheets are rejected atomically. Loan rows can be omitted to record no payment; preview still shows unpaid bills for that member.

Every HTTP import first returns a preview, without persisted writes. It shows savings and each Loan ID's authoritative bill, actual, signed difference, unpaid amount, deferred amount and any collection already recorded for that statement month. Accounting and suspension validation run in a rollback-only transaction. Missing journal mappings reject new operations instead of creating pending journals. The importer does not use displayed totals or summary loan columns as authority for payments.

Confirmation requires a thirty-minute HMAC-signed token binding the user, statement month, receipt date, exact file bytes and authoritative member/configuration/loan/schedule/receipt state. State is reloaded under member, configuration, loan and installment locks before comparison. Changed state or file requires another preview. Browser confirmation carries the same bounded workbook in a hidden encoded field; API clients resubmit the same file and preview_token. No schema migration or persistent preview storage is needed.

All savings, loan payments, suspension operations and journals commit together. Matching re-imports after another preview skip already recorded collections for each loan independently. Changing a loan's already imported amount is rejected and requires the existing correction workflow. A different file cannot silently adjust or refund earlier receipts.

Legacy `Penangguhan Cicilan` and `LoanSuspensions` imports remain supported when no detail sheet is present; both legacy sheets together are rejected. Legacy aggregate loan payments are rejected when several loans of one type are involved; re-export is required to disambiguate the Loan IDs. Every legacy import still requires preview and confirmation.

Savings do not support partial realization or skip instructions in this workflow. Only actual loan repayments reduce loan remaining balances. Suspension fees remain separate revenue on COA 40201.
